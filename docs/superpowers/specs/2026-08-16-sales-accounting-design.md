# Учёт прибыли при #продано — дизайн (бета)

## Проблема

Админ хочет знать прибыль по каждой продаже (закупка vs продажа), не считая это вручную.
Сейчас при добавлении `#продано` в пост канала бот только помечает товар `SOLD`
([bot/handlers/channel.py:699](../../../bot/handlers/channel.py)) — данных о деньгах нет.

## Решение

### Хранение

Новая таблица `sales` (SQLAlchemy модель в `database/models.py`, аналогично `Product`):

| поле | тип | комментарий |
|---|---|---|
| `id` | PK | |
| `product_id` | FK → `products.id` | |
| `purchase_amount` | Numeric | |
| `purchase_currency` | str | напр. `EUR`, `PLN`, `USD`, `USDT` |
| `sale_amount` | Numeric | |
| `sale_currency` | str | |
| `profit` | Numeric, nullable | считается только если валюты совпали |
| `recorded_by_admin_id` | int | telegram id того, кто ответил боту |
| `created_at` | datetime | |

Отдельная таблица, а не поля в `Product` — это разовое бухгалтерское событие, а не свойство товара.

### Конфиг (`config.py`, по паттерну существующих `Settings`/env)

- `ACCOUNTING_ADMIN_IDS: list[int]` — кому бот пишет в ЛС за цифрами (не обязательно совпадает с `ADMIN_IDS`)
- `GOOGLE_SHEET_ID: str`
- `GOOGLE_SERVICE_ACCOUNT_JSON: str` — ключ сервис-аккаунта, JSON целиком в env-переменной, парсится `json.loads` в рантайме

Настройка сервис-аккаунта Google Cloud — ручные шаги через консоль, отдельная инструкция, не автоматизируется.

### FSM-диалог

В проекте нет прецедента многошаговых диалогов (проверено: нет `StatesGroup`/`FSMContext` нигде в `bot/`).
Добавляем aiogram 3 FSM с `MemoryStorage` — новый модуль `bot/handlers/accounting.py`.

Состояния: `AccountingStates.awaiting_purchase`, `AccountingStates.awaiting_sale`.
Ввод в формате `<число> <валюта>` (напр. `120 EUR`), парсится регэкспом `^(\d+(?:\.\d+)?)\s*([A-Za-zА-Яа-я]+)$`.

**Триггер**: сразу после коммита `product.status = SOLD` в
`on_edited_channel_post` ([bot/handlers/channel.py:699-706](../../../bot/handlers/channel.py)), не меняя существующую логику этой функции —
добавляется вызов `start_accounting_dialog(bot, product)`.

**Поток**:
1. Если для `product_id` уже есть запись в `sales` — ничего не делать (защита от повторного запуска на дубли-эдиты).
2. Для каждого `admin_id` в `ACCOUNTING_ADMIN_IDS`: отправить ЛС «Продано: {brand} {name}. Закупка? (напр. `120 EUR`)», установить состояние `awaiting_purchase` с `product_id` в FSM data (состояние — per-chat, конфликтов между админами нет).
3. Ответ → парсинг → если не распарсился, переспросить, не продвигая состояние. Если ок — сохранить в FSM data, перейти в `awaiting_sale`, спросить цену продажи в том же формате.
4. Второй ответ → аналогичный парсинг → создать строку `sales` → если `purchase_currency == sale_currency`, посчитать `profit = sale_amount - purchase_amount`, иначе `profit = NULL` → попытаться дописать строку в Google Sheet → отправить «Записано ✅» (или «записано, но в таблицу не ушло — гляну позже» при сбое синка).
5. Если второй админ пытается ответить на уже записанный товар (проверка на момент сохранения) — «уже внесено», без дубликата строки.
6. `/cancel` — сброс FSM-состояния в любой момент диалога.
7. Таймаута нет — состояние ждёт ответа сколько угодно (по решению пользователя).

### Google Sheets

Новый модуль `bot/sheets.py`, обёртка над `gspread` (service account auth).
Функция `append_sale_row(brand, name, purchase_amount, purchase_currency, sale_amount, sale_currency, profit, admin_username)`.

Колонки таблицы: `Дата | Бренд | Название | Закупка | Валюта закупки | Продажа | Валюта продажи | Прибыль | Кто внёс`.

Сбой синка (сеть/протухший токен) не блокирует сохранение в БД — БД первична, лог warning, админу — уведомление о несинке.

## Beta-ограничения (сознательно не делаем сейчас)

- Нет конвертации валют между закупкой и продажей — прибыль считается только при совпадении валют.
- Нет редактирования уже внесённой записи через бота — правки вручную в БД/таблице.
- Нет ретраев/очереди для сбоившего синка с Sheets — только уведомление, досинк вручную при необходимости.

## Тестирование (бета)

Ручное: пометить тестовый товар `#продано` в канале → проверить ЛС-диалог → проверить строку в БД (`sales`) → проверить строку в Google Sheet.
